01 El entorno

El entorno de trabajo:
VS Code + Claude Code

⌨️

VS Code

Editor de texto gratuito. No requiere saber programar: organiza la carpeta del proyecto — plan, notas, bibliografía, borradores — en un solo lugar.

🤖

Claude Code

Agente de IA integrado en VS Code (o en la terminal). Recibe instrucciones en español y puede leer y escribir archivos del proyecto, buscar en la web y ejecutar código.

🧭

¿Qué es un agente?

Un chatbot responde. Un agente planifica, ejecuta tareas con herramientas, verifica el resultado e itera hasta terminar — bajo las reglas que se le fijen. Esa diferencia define todo el método.

💡 Sobre la herramienta: este tutorial y su proyecto de ejemplo se construyeron con Claude Code (Anthropic); por eso es la vía destacada en cada paso. El método es transferible: OpenAI Codex y Google Antigravity ofrecen los mismos bloques — un agente, reglas de proyecto y un editor o terminal — y sus equivalentes se indican a lo largo de la página.

🗂️
Paso C — Crear la carpeta con esta estructuraArchivo → Abrir carpeta · la estructura se le pide al agente · ~3 min

Crear una carpeta para la investigación y abrirla en VS Code (Archivo → Abrir carpeta). Antes del primer prompt "de investigación", conviene definir cómo se organiza el proyecto. Esta estructura — la misma del caso de este tutorial — permite que cualquier lector (un jurado, un par evaluador, un director) reconstruya qué se hizo y de dónde salió cada cosa:

mi-investigacion/
├── CLAUDE.md            ← el arnés: reglas que el agente lee siempre
├── plan.md              ← pregunta, hipótesis, etapas, criterios
├── prompts/             ← registro de prompts (memoria metodológica)
├── datos/               ← resultados de búsquedas, con fecha
├── bibliografia/
│   ├── matriz_q.xlsx    ← qué responde cada fuente a cada pregunta
│   ├── metadatos/       ← ficha JSON por artículo (OpenAlex)
│   └── pdf/             ← solo PDFs cuya licencia permite descarga
├── artefactos/          ← SVG, HTML, JS — cada uno con su prompt
└── articulo/            ← borradores [BORRADOR-IA] y versión firmada
  • La estructura es el método. Separa lo que se piensa (plan.md), lo que se encuentra (datos/, bibliografia/), lo que se produce (artefactos/, articulo/) y cómo se hizo (prompts/).
  • Cada carpeta responde una pregunta del evaluador. ¿De dónde salió este dato? ¿Con qué búsqueda? ¿Qué prompt produjo este diagrama?
  • CLAUDE.md es la primera piedra. El agente lo lee al iniciar cada sesión: contiene las reglas innegociables del proyecto. Equivalentes: AGENTS.md en Codex (estándar abierto) y GEMINI.md / AGENTS.md en Antigravity.
  • Git como memoria (opcional): cada cambio queda en la historia del repositorio.

El primer prompt del proyecto: pedir la estructura.

Crea en esta carpeta la estructura de un proyecto de investigación
con buenas prácticas: CLAUDE.md (las reglas del proyecto), plan.md,
y las carpetas prompts/, datos/, bibliografia/ (con metadatos/ y
pdf/), artefactos/ y articulo/. Escribe en cada carpeta un README.md
de una línea que explique qué guarda y qué NO debe guardarse ahí.
Muéstrame el árbol completo antes de crear nada.

¿Qué tan "agente" es la herramienta? la agencia es un espectro, no un interruptor

Los chatbots actuales ya ejecutan tareas agénticas: buscan en la web, hacen cálculos, leen documentos. La diferencia entre "chatbot" y "agente" no es un interruptor de encendido y apagado, sino una escalera: en cada peldaño la herramienta hace más por su cuenta — más iniciativa, más herramientas, verificación propia y un entorno más amplio (los archivos del proyecto).

1Modelo que responde

Texto entra, texto sale. Sin herramientas ni memoria del proyecto. Toda la iniciativa es del usuario, turno a turno.

los primeros chatbots (2020–2022)
2Chatbot con herramientas

Ejecuta tareas agénticas puntuales a pedido: busca en la web, corre un cálculo, lee un documento. Un paso a la vez.

ChatGPT, Claude, Gemini (hoy)
3Agente

Encadena pasos hacia una meta: planifica, elige qué herramienta usar y cuándo, verifica el resultado e itera sin que se le dicte cada paso.

Claude Code · Codex · Antigravity · Copilot
4Agente con entorno y reglas

Trabaja además sobre el proyecto — lee y escribe sus archivos — y bajo reglas persistentes. Cada acción queda registrada.

Claude Code + CLAUDE.md — el caso de este tutorial
💡 En palabras simples: aquí "agencia" significa una sola cosa — cuántos pasos puede dar la herramienta por su cuenta. Un chatbot da un paso y espera; un agente encadena varios hacia una meta. Y suba lo que suba en la escalera, las decisiones importantes y la responsabilidad por el resultado siguen siendo del investigador. La pregunta práctica: ¿cuántos pasos se le delegan, y con qué reglas? — para eso existe el arnés.

El ciclo del agente (clic en cada etapa)

Este ciclo separa los peldaños 3 y 4 del resto: un chatbot responde y espera la siguiente instrucción; un agente recorre planificar → ejecutar → verificar → iterar hasta cumplir la meta asignada. En cada etapa, el investigador tiene un papel definido:

Planificar. El agente descompone la instrucción en pasos: "para buscar literatura se necesita la pregunta, luego la ecuación, luego ejecutarla, luego registrar los conteos". En Claude Code — la herramienta de este tutorial — puede exigirse ver el plan antes de que toque un archivo; Codex y Antigravity tienen modos equivalentes.

👤 Papel del investigador: corregir el plan — quitar pasos, añadir criterios, acotar el alcance. Corregir un plan cuesta menos que corregir un resultado.

02 El caso

De la afirmación de un video
a una pregunta de investigación

«La IA ROMPE a los trabajadores que MEJOR la usan» — Xavier Mitjana, YouTube, abril de 2026 · ver en YouTube ↗
▶

Un titular provocador. En investigación, las afirmaciones provocadoras no se comparten ni se refutan por reflejo: se convierten en preguntas. Ese es el ejercicio completo de este tutorial: del titular al artículo.

💡 Antes de seguir: ¿se comparte la intuición del titular? Anotar la respuesta — y volver a hacerse la pregunta al final del recorrido.

De titular a pregunta de investigación

¿En qué medida el uso intensivo de asistentes de IA afecta la carga cognitiva, la memoria y el pensamiento crítico de sus usuarios más frecuentes?

  • Q1 ¿Delegar en la IA reduce el esfuerzo cognitivo invertido (descarga cognitiva)?
  • Q2 ¿Qué efectos se han medido sobre memoria y pensamiento crítico?
  • Q3 ¿Quiénes son más vulnerables y bajo qué condiciones de uso?

H1: la IA usada como sustituto del esfuerzo se asocia con menor retención y evaluación crítica. H0: no hay asociación medible.

03 El plan y los prompts

Primero el plan,
luego los prompts

Todo proyecto de investigación recorre la misma ruta: identificar un problema, convertirlo en una pregunta precisa, anticipar una hipótesis y fijar un objetivo. Con agentes, la ruta no cambia: cambia la velocidad. El agente sigue el plan del investigador — nunca al revés.

Clic en cada etapa: método, prompts sugeridos y arnés.

Cómo pedirle al agente: las 6 piezas de un prompt

Un prompt de investigación no es una pregunta suelta: es una instrucción con seis piezas. La cuarta — el arnés — es la que evita los problemas típicos: referencias inventadas, resultados sin registro, pasos sin verificación.

1 Rol quién debe ser la IA 2 Contexto qué debe leer o saber antes 3 Tarea qué debe producir, en concreto 4 Arnés qué tiene prohibido hacer 5 Formato cómo debe entregarlo 6 Verificación cómo se sabrá que está bien

✗ Prompt débil

Búscame artículos sobre IA y cognición
y hazme un resumen.

Sin criterios, sin arnés, sin registro. El resultado: una lista imposible de auditar y, tarde o temprano, una referencia inventada.

✓ Prompt fuerte

Actúa como asistente de revisión sistemática. [ROL]
Lee plan.md: ahí están mis preguntas Q1–Q3. [CONTEXTO]
Construye la ecuación de búsqueda y ejecútala
en OpenAlex; lista los 15 más citados con su
URL de acceso explícita. [TAREA]
No inventes referencias: solo resultados con DOI;
si algo no aparece, dilo. [ARNÉS]
Guarda el JSON en datos/ y dame una tabla:
título, año, DOI, URL, citas. [FORMATO]
Registra la ecuación exacta y los conteos
por etapa para el PRISMA. [VERIFICACIÓN]

Etapa 1 · El problema

    
Definir qué ocurre — y por qué importa

    
El método: para llegar a la raíz de un problema existen tres técnicas
    clásicas:

    

      
❓ 5 Porqués
Método interrogativo para llegar a la causa raíz.

      
🌳 Árbol de Problemas
Representación gráfica de causas y efectos.

      
⚖️ Campo de Fuerzas
Fuerzas impulsoras vs. restrictivas del problema.

    

    
Objetivo del paso: llegar a la causa raíz sin que la IA invente el
    problema. El problema debe ser genuino: del investigador.

    

      
Actúa como tutor metodológico. Vamos a aplicar la técnica de los
5 porqués al tema "el uso intensivo de IA y la carga cognitiva de
sus usuarios". Tu papel es SOLO hacer las preguntas, una a la vez,
y pedirme evidencia de cada respuesta. No respondas por mí.
Al final, resume MI cadena causal en un árbol de problemas
(causas → problema central → efectos) y señala en qué eslabones
me falta evidencia.

      
    

    
🪢 Arnés: la IA pregunta, el investigador responde.
    Si el agente propone el problema, está eligiendo la investigación por él.

    
💡 Tip: exigir evidencia (cifras, fuentes) en cada
    eslabón causal. Un problema sin datos es todavía una opinión.

    
📄 Artefacto: sección "problema" de plan.md (5 porqués + árbol).

   

  


  

   

    
Etapa 2 · Pregunta e hipótesis

    
Una pregunta precisa, hipótesis contrastables

    
El método: tres pruebas clásicas para evaluar una pregunta de
    investigación. Debe pasar las tres:

    

      
✔ FINER pertinencia
Factible · Interesante · Novedosa · Ética · Relevante

      
⚙ PICO estructura
Población · Intervención · Comparación · Outcome (resultado)

      
↔ Causal-propositiva relación
"¿Cómo [X] afecta [Y] en [población] durante [tiempo]?"

    

    

      
Aquí está mi borrador de pregunta: "¿Cómo afecta la IA la carga
cognitiva de sus usuarios más acérrimos?". Evalúala contra tres
pruebas: FINER (¿es factible, interesante, novedosa, ética,
relevante?), PICO (¿tiene población, intervención, comparación y
outcome?) y causal-propositiva (¿conecta X con Y en una población
y un tiempo?). Propón 3 reformulaciones que pasen LAS TRES pruebas,
y dime qué pierde y qué gana cada una.
No elijas por mí: yo decido.

      
    

    
Segundo prompt — las hipótesis:

    

      
Con la pregunta elegida, formula H0 y H1 con una métrica observable
y di qué evidencia permitiría contrastarlas. Señala también qué
diseño NO serviría para responderlas, y por qué.

      
    

    
🪢 Arnés: la IA critica y propone; la decisión queda
    registrada como del investigador. La hipótesis nace del análisis, no del prompt.

    
💡 Tip: una pregunta que no nombra población ni contexto
    todavía no es una pregunta de investigación.

    
📄 Artefacto: pregunta central + Q1–Qn + H0/H1 en plan.md.

   

  


  

   

    
Etapa 3 · Objetivos

    
Del interrogativo al declarativo

    
El método: el objetivo traduce la pregunta en acción.
    Regla práctica: si la pregunta dice "¿en qué medida…?", el objetivo dice
    "determinar en qué medida…".

    

      
El objetivo general debe ser SMART

      

        S EspecíficoM MedibleA AlcanzableR RelevanteT Temporal
      

      
Estructura recomendada: verbo en infinitivo + qué + cómo + para qué + dónde/cuándo.

    

    

      
Convierte mi pregunta central (léela en plan.md) en un objetivo
general SMART y en 3 objetivos específicos que lo agoten.
Verifica la coherencia: cada específico debe responder a una
pregunta auxiliar; si alguno no responde a ninguna, dilo.

      
    

    
🪢 Arnés: ningún objetivo sin pregunta que lo respalde;
    ninguna pregunta sin objetivo que la atienda.

    
💡 Tip: preferir verbos medibles (comparar, clasificar,
    medir, contrastar) sobre verbos difusos (conocer, comprender, reflexionar).

    
📄 Artefacto: objetivo general + específicos en plan.md.

A partir de mis preguntas Q1–Q3 (léelas en plan.md), aplica los
5 pasos: extrae los conceptos clave con PICO,
expande sinónimos en inglés ("cognitive offloading", "cognitive
debt", "generative AI", "large language models") y arma la
ecuación booleana. Ejecútala contra la API de OpenAlex, guarda el
JSON en datos/busqueda_2026-07-30_openalex.json y registra:
ecuación exacta, total identificado, filtros y total tras filtros.
NO selecciones todavía: lista los 15 más citados con título, año,
DOI, conteo de citas, la URL de acceso explícita de cada uno y si
su ABSTRACT está disponible en una fuente verificable (editor,
PubMed, arXiv, Semantic Scholar, Crossref). Prioriza las fuentes
con abstract disponible.

      
    

    
🪢 Arnés: conteos por etapa (insumo del PRISMA), URL y
    disponibilidad de abstract por resultado. La selección la hace el investigador.

    
Segunda parte — descargar el material y llenar la Matriz Q: completar
    PDF y abstract de cada fuente elegida, y extraer qué responde a cada pregunta
    con cita localizable.

    

      
De los artículos que seleccioné (marcados en datos/seleccion.md),
primero completa el material: descarga a bibliografia/pdf/ los PDF
de acceso abierto cuya licencia lo permita (incluye repositorios
institucionales y espejos legítimos) y registra el abstract real
de cada fuente (editor, PubMed, arXiv, Semantic Scholar o
Crossref); guarda los metadatos de TODOS en bibliografia/metadatos/.
Si un editor bloquea la descarga automatizada o el artículo es de
pago, NO evadas el bloqueo: registra la URL en descargas.md.
Después llena bibliografia/matriz_q.csv: referencia APA, año, DOI,
URL, abstract, PDF en el proyecto, qué responde a Q1, Q2 y Q3
(con cita textual y sección) y qué vacío deja.
REGLA DURA (criterio de usabilidad): las preguntas SOLO pueden
responderse desde fuentes con PDF descargado y/o abstract real;
lo demás queda como SOLO-REFERENCIA y no responde nada. Si un
artículo no dice nada sobre una pregunta, escribe "no aborda".
Marca cada fila PENDIENTE-VALIDAR hasta que yo la revise.

      
    

    
🪢 Arnés — criterio de usabilidad: una fuente solo
    sustenta afirmaciones con PDF descargado y/o abstract real registrado, más la referencia
    verificada; descargas solo con licencia; "no aborda" en vez de relleno. El investigador
    valida cada fila.

    
💡 Tip: registrar los conteos de cada búsqueda desde el
    primer día: el diagrama PRISMA se arma solo.

Etapa 5 · Metodología

    
Cómo se responderá la pregunta

    
El método: un diseño metodológico completo declara cinco decisiones:

    
    
      
  • Enfoque — cualitativo, cuantitativo o mixto, según la pregunta.
    • 
      
  • Diseño y alcance — exploratorio, descriptivo, correlacional, experimental…
    • 
      
  • Población, muestra o corpus — quiénes o qué, y por qué.
    • 
      
  • Técnicas e instrumentos — entrevistas, encuestas, análisis documental, mediciones.
    • 
      
  • Consideraciones éticas — consentimientos, anonimización, manejo de datos.
    • 
    

    

      
Lee plan.md y bibliografia/matriz_q.csv. Propón DOS diseños
metodológicos viables para responder Q1–Q3: uno cualitativo y uno
mixto. Para cada uno: población o corpus, instrumentos,
procedimiento y limitaciones. Preséntalos en una tabla comparativa
de ventajas y riesgos. No elijas por mí.

      
    

    
🪢 Arnés: la IA compara opciones; el diseño lo decide y
    lo justifica el investigador. Consentimientos y datos personales no se delegan.

    
💡 Tip: el diseño se defiende con la coherencia
    pregunta ↔ objetivo ↔ método. Si un método no responde a ningún objetivo, sobra.

    
📄 Artefacto: sección "metodología" de plan.md.

   

  


  

   

    
Etapa 6 · Datos y análisis

    
Recolectar y analizar, dejando rastro

    
El método: los datos crudos se conservan intactos; todo procesamiento
    ocurre por scripts guardados en el proyecto, de modo que el análisis pueda repetirse.

    

      
Escribe un script que procese los archivos de datos/ y genere las
tablas y figuras del análisis descritas en plan.md. Guarda el
código y las salidas en artefactos/. Reglas: no modifiques los
datos crudos; registra fecha y versión de cada salida; si un dato
falta o es dudoso, repórtalo en vez de imputarlo en silencio.

      
    

    
🪢 Arnés: datos crudos intocables; toda figura nace de
    datos reales con su código en el repositorio; los datos sensibles se anonimizan antes de
    procesar.

    
💡 Tip: un análisis que no puede repetirse con un clic
    no está terminado.

    
📄 Artefacto: datos/ (crudos y procesados)
    + artefactos/ (scripts, tablas, figuras).

   

  


  

   

    
Etapa 7 · Resultados y discusión

    
Separar el hallazgo de su interpretación

    
El método: primero qué se encontró (resultados), después qué significa
    (discusión), siempre en contraste con las hipótesis y con la literatura de la Matriz Q.

    

      
Contrasta los resultados de artefactos/ con H0 y H1 y con la
matriz Q: qué se confirma, qué se contradice, qué queda abierto.
Propón interpretaciones alternativas que yo no haya considerado
y lista los límites que debo declarar. Marca todo como
[BORRADOR-IA].

      
    

    
🪢 Arnés: correlación no es causalidad; los límites se
    declaran; la interpretación la firma el investigador.

    
💡 Tip: un resultado incómodo no se omite: se discute.

    
📄 Artefacto: borrador de resultados y discusión
    [BORRADOR-IA] en articulo/.

   

  


  

   

    
Etapa 8 · Comunicación

    
Contar lo encontrado — y firmarlo

    
Artículo académico, tesis o divulgación: el género cambia según la audiencia; las
    reglas de autoría no. Todo cierre incluye la declaración de uso de IA (sección 05).

    

      
Con la Matriz Q validada, redacta un BORRADOR de artículo de prensa
(800 palabras, tono divulgativo, titular atractivo pero honesto) que
responda al video "La IA ROMPE a los TRABAJADORES que MEJOR la
usan": qué dice realmente la evidencia. Reglas: cada afirmación
empírica cierra con (Autor, año); distingue correlación de
causalidad; incluye una sección "lo que todavía no sabemos"; nada
de cifras que no estén en la matriz. Márcalo [BORRADOR-IA].
Yo lo reescribo, lo firmo y añado la declaración de uso de IA.

      
    

    
🪢 Arnés: el borrador se marca como borrador; el texto
    final lo firma una persona que responde por él.

    
💡 Tip: la declaración de uso de IA no se escribe al
    final: se va llenando durante el proyecto (el registro de prompts ya la contiene).

    
📄 Artefacto: articulo/ —

04 Agentes y artefactos

  
Tres agentes,
muchos artefactos

  
En los agentes de código pueden definirse subagentes
  especializados: archivos de texto que describen un rol, sus herramientas y sus
  reglas. Los de este proyecto son tres: buscador,
  sintetizador y visualizador. Así se define el buscador
  en cada herramienta:


  

    
    
    
  


  

    

      .claude/agents/buscador.md — subagente de Claude Code

    
---
name: buscador
description: Busca literatura académica y registra conteos PRISMA
tools: WebFetch, WebSearch, Read, Write
---
Eres el agente buscador del proyecto. Sigue las reglas de CLAUDE.md:
solo fuentes con DOI verificable y URL de acceso explícita; guarda
toda búsqueda en datos/ con fecha, ecuación exacta y conteos por
etapa. Si no encuentras algo, dilo: nunca rellenes con resultados
plausibles.

    
Las reglas generales viven en CLAUDE.md; cada subagente
    de .claude/agents/ añade su rol y sus herramientas permitidas.

  


  

    

      AGENTS.md — instrucciones que Codex lee antes de actuar

    
# AGENTS.md (raíz del proyecto)

## Rol: buscador
Cuando la tarea sea buscar literatura académica:
- Solo fuentes con DOI verificable y URL de acceso explícita.
- Guarda toda búsqueda en datos/ con fecha, ecuación exacta y
  conteos por etapa (PRISMA).
- Si no encuentras algo, dilo: nunca rellenes con resultados
  plausibles.

    
AGENTS.md es un estándar abierto (hoy de la Linux
    Foundation): también lo leen Cursor, Copilot y otras herramientas. Puede haber uno por
    carpeta; el más cercano al archivo editado tiene prioridad.

  


  

    

      .agents/agents/buscador.md — agente del espacio de trabajo de Antigravity

    
# .agents/agents/buscador.md

Nombre: buscador
Misión: buscar literatura académica y registrar conteos PRISMA.
Reglas (además de las del proyecto en GEMINI.md / .agents/rules/):
- Solo fuentes con DOI verificable y URL de acceso explícita.
- Toda búsqueda queda en datos/ con fecha, ecuación y conteos.
- Ante la duda, reportar en vez de rellenar.

    
En Antigravity los agentes se lanzan y supervisan desde el
    Gestor de Agentes (varios en paralelo); las reglas del proyecto viven en
    GEMINI.md o AGENTS.md y en .agents/rules/.

  


  
La estructura es equivalente en las tres herramientas: un archivo de texto
  con rol + reglas. Este proyecto se construyó con Claude Code; por eso es la pestaña
  resaltada.

    Diagrama conceptual (SVG)

esfuerzo → menor retención → mayor dependencia → delegar más.
Junto a cada eslabón indica la referencia de la Matriz Q que lo

  solo nacen de datos reales del proyecto (sección 05).
    
  
    

    



    
  
    
  
    05 La autoría del investigador
    
  
    Cuatro modos de escribir con IA
    sin dejar de ser el autor
    

  
    
    
    
      
    4.1
    
      
    Escritura directa,
    IA como validadora
    
      
    El investigador escribe; la IA revisa: lógica, estilo, contraejemplos, claridad.
      Es el modo que más protege la voz propia.
    
      
    ⚠️ Datos sensibles: no pegar en ningún servicio datos
      personales, entrevistas sin anonimizar ni material inédito de terceros. Anonimizar
      primero; revisar la política institucional.
    
    
    
    
    
      
    4.2
    
      
    El diálogo como
    ejercicio autoral
    
      
    La IA puede dialogar para definir, refinar o corregir el problema:
      "haz preguntas", "critica este argumento", "da el contraargumento más fuerte".
    
      
    Pensar con la IA es legítimo — siempre que quien decide, y quien queda
      registrado decidiendo, sea el investigador.
    
    
    
    
    
      
    4.3
    
      
    Los artefactos
    adecuados
    
      
    Pedirle: estructuras y planes, matrices de literatura, diagramas
      conceptuales, código de análisis, resúmenes de textos ya leídos.
    
      
    No pedirle: texto final para firmar sin revisar, referencias "de
      memoria", datos o resultados, ni la pregunta de investigación.
    
    
    
    
    
      
    4.4
    
      
    Principios de
    las imágenes
    
      
    Sí: diagramas conceptuales e ilustraciones, declarados como generados.
    
      
    Solo con datos reales: todo gráfico de resultados, con su código
      reproducible en el repositorio.
    
      
    Nunca: crear o alterar imágenes de apariencia científica.
    
    
    
  
    

  
    Lo que ya dicen las editoriales
    
  
    
    
    COPELa IA no cumple los requisitos de autoría; los autores responden y declaran su uso.
    
    
    ElsevierIA para legibilidad con supervisión y declaración; prohibida como autora o para crear/alterar imágenes.
    
    
    SpringerLos LLM no pueden ser autores; el uso se documenta en métodos.
    
    
    WileyTransparencia: qué herramienta y para qué; el humano responde por exactitud e integridad.
    
    
    IEEEEl uso de IA en el texto se declara; la responsabilidad es de los autores.
    
  
    

  
    
    
    
      
    Ejemplo de declaración
    
      «Durante la preparación de este trabajo se utilizó Claude Code (Anthropic) para la
      búsqueda y organización preliminar de la literatura y la construcción de la matriz de
      síntesis, bajo las reglas del archivo CLAUDE.md del proyecto. El autor verificó cada
      referencia en su fuente original, reescribió el texto y asume plena responsabilidad
      por su contenido.»
    
    
    
    
      
    ComprenderNo incluir nada que no pueda explicarse y defenderse ante un par evaluador.
    
      
    RevisarEditar y validar todo texto o análisis generado antes de incorporarlo.
    
      
    AsumirEl investigador responde por cada palabra, dato y cita — las haya escrito él o una máquina.
    
    
    
  
    
  
    Regla simple: ante la duda entre declarar o no declarar, declarar.
  La transparencia nunca perjudica; la omisión sí.
